Path Trace Debugger

Real-time path tracing of the Nanite cluster pipeline: the same clusters, the same LOD cut and the same materials as the rasterizer, traced in a compute kernel through a static cluster hierarchy that chooses the cut while a ray walks it. No hardware ray tracing, no per-frame BVH build. starting

Scene

Every mesh's clusters and LOD DAG live in one merged set; the tracer adds a triangle BVH per cluster and one hierarchy per mesh over every level, built once. Instances get a small TLAS on the CPU each frame.

Path tracing

Each frame adds one path per pixel: a camera ray, the sun through a shadow ray at every hit, the sky through the sampled bounce. Moving the camera restarts the sum. The left part of the split shows the raster pipeline's own frame.

What runs each frame

Raster (left of the split): the cull kernel over every (instance, cluster) pair (frustum, cone, LOD cut) and one indirect draw. Path tracing: a CPU TLAS over the instances, then per bounce a trace kernel (one thread per pixel: TLAS → the mesh's cluster hierarchy, skipping subtrees whose largest parent error projects below the threshold or whose smallest own error projects above it, applying the cull kernel's cut rule at each cluster, then the cluster's triangle BVH through the mesh's own corner fetch) and a shade kernel (material table, GGX + Lambert, a shadow ray towards the sun disk, a sampled next direction, Russian roulette). The display quad divides the sums by the sample count; the debug views are drawn from the primary hit record.
